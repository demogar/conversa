# Internationalisation

Conversa ships in **English** (`en`, the default) and **Spanish** (`es`, Latin American, addressing the reader as `tú`).

## How it works

- **The API sends no prose.** Errors are stable codes (`ErrorCode` in `packages/shared/src/errors.ts`), validation problems are field paths with short codes (`required`, `keywords_required`). The web app translates them in `messages/<locale>/errors.json` (`codes` and `fields`).
- **The web app** uses `next-intl` without locale routing (no `/es/` in URLs). The locale is, in order: the `conversa_locale` cookie (set when someone picks a language or signs in), then the browser's `Accept-Language`, then English. A signed-in person's choice is also saved on their account.
- **Messages** are one JSON file per area: `apps/web/messages/<locale>/<area>.json`, merged by `messages/<locale>/index.ts`. The English tree types the keys used in code (`src/i18n/types.ts`), so a key missing from English fails `tsc`. Nothing yet checks that the other locales have the same keys, so compare the files when you change them.
- **Mola UI's own words** (its components' built-in labels: "Close", pagination, dates) are translated in `apps/web/src/i18n/mola-<locale>.ts` and passed to Mola's `MessagesProvider`.
- **Email** (invitations, password resets) is rendered by the API in `apps/api/src/infra/mail/templates.ts`.
- **Dates and numbers** use `Intl` with `FORMAT_LOCALE` (`en-US`, `es-419`).

## Adding a string

Add the key to **both** `messages/en/<area>.json` and `messages/es/<area>.json`, same path, then use it with `useTranslations('<area>')`. See `.claude/commands/add-locale-string.md` for the checklist. Write each language naturally; do not translate word for word.

## Adding a language

Using Portuguese (`pt`) as the example.

1. **Shared**: in `packages/shared/src/enums.ts`, add `PT: 'pt'` to `Locale` and to `LOCALES`. Schemas that accept a locale read `LOCALES`, so the API accepts it from then on.
2. **Messages**: copy `apps/web/messages/en/` to `apps/web/messages/pt/` and translate every file. Keep `index.ts` identical in shape.
3. **Loader**: add `pt: () => import('../../messages/pt')` to `loaders` in `apps/web/src/i18n/request.ts`.
4. **Types**: add `'pt'` to the `Locale` union in `apps/web/src/i18n/types.ts`.
5. **Formatting**: add `pt: 'pt-BR'` (or the region you mean) to `FORMAT_LOCALE` in `apps/web/src/i18n/config.ts`.
6. **Language picker**: add `"pt": "Português"` to `language` in `messages/*/common.json` for **every** locale, written in the language's own name.
7. **Mola UI**: create `apps/web/src/i18n/mola-pt.ts` (start from `mola-es.ts`) and add it to `molaMessages` in `src/i18n/mola.ts`.
8. **Server-side text**: add the language's branch to each template in `apps/api/src/infra/mail/templates.ts`, and to the few other places the API writes text for a person (search `apps/api/src` for `=== 'es'`, for example the default name of a new account's first workspace).
9. **Legal pages**: `messages/pt/legal.json` holds the privacy policy, terms and data deletion text. Have them reviewed; they are what Meta's app review reads.
10. Run `pnpm check`, then open the app with the language selected and walk every screen. Look for overflow: some languages run 30% longer than English.

## Style

- Sentence case for labels and titles.
- Buttons start with a verb and name the object: "Connect Buffer", "Delete automation".
- Say what happened and what to do next in errors; never show an error code alone.
- Placeholders use ICU syntax: `"Due {date}"`, plurals with `{count, plural, one {# contact} other {# contacts}}`.
